<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| model endpoint -> detective-mode tool calls | The remote model chooses which `read_file` paths to request and what `finish` proposal to submit; both are untrusted input to the driver's virtual filesystem and to workflow.apply_proposal's existing validation. |
| virtual filesystem -> model | The driver decides what the model can read; this boundary must never expose validation/test-split answers or markers, matching the existing proposer_context() guarantee that only train_outcomes reach the Proposer. |
| detective-mode finish() -> workflow.apply_proposal | The proposal's stated trace_ids and context_hash are claims about what the model actually did; the driver must verify provenance (reads log) rather than trust the model's self-report, and must never forward a model-computed context_hash. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-260923-06 | Spoofing | detective-mode finish() trace_ids claim | high | mitigate | The driver cross-checks every cited trace_id against its own reads log (not the model's claim) before forwarding to apply_proposal; a cited-but-unread id is refused once then raises. Covered by test_run_proposer.py's unread-trace-id test. |
| T-260923-07 | Tampering | model-supplied context_hash in finish() payload | high | mitigate | The driver always overwrites context_hash with its own sha256 of the exact proposer_context() bytes before calling apply_proposal; apply_proposal's own validate_proposal check (context_hash must equal sha256 of proposer_context) provides a second independent gate even if the driver-side overwrite were ever removed. |
| T-260923-08 | Information Disclosure | virtual filesystem path exposure | critical | mitigate | read_file only resolves exact-match keys built from proposer_context()'s train_outcomes, wiki_pages, impact_history, and active_skill — all already train-split-only by the existing evidence.py/proposal.py split checks. No filesystem path traversal, no validation/test split content, and no literal disk access occurs; refused paths are logged, not served. Covered by test_run_proposer.py's out-of-scope-read and path-traversal tests. |
| T-260923-09 | Denial of Service | unbounded detective-mode loop | medium | mitigate | --max-turns (default 20) hard-caps the loop; reaching the cap raises ContractError rather than looping forever, mirroring the Maintainer driver's bounded-retry precedent from plan 01. |
| T-260923-10 | Repudiation | missing read provenance | medium | mitigate | Every read_file call (successful or refused) is logged with path, content hash, and turn number to a persisted reads log under the run directory, giving a complete, order-preserving audit trail independent of the model's own narrative. |
</threat_model>
