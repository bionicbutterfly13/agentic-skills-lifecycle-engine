## Settled decisions (source: decision-ledger.md, this plan only records them)

- Q1 (ledger lines 8-10): method parity first — loop runs the paper's four roles with the
  paper's prompts on one domain, no numbers claimed. Empirical parity on one benchmark
  revisited after one real end-to-end run. Full reproduction not scheduled.
- Q2 (ledger lines 11-14): bare local model via a new direct adapter (Ollama on the dev
  machine: hermes3 4.7 GB, deepseek-r1 5.2 GB; Intel i7, 16 GB, CPU-only). Host adapters
  (Hermes, Codex, Claude Code) come after the loop is proven. ASME's OpenAI-only routing
  control is inherited history, not Lifecycle authority.
- Q3 (ledger lines 15-17): confirmation run is a study-manifest switch. Off for runs labelled
  paper_comparable (one validation run, strict >, matches Algorithm 1). On for production
  promotion (two strict wins, score = min(val, confirm)).
- Q4 (ledger lines 18-20): Proposer mode is detective (multi-turn ReAct, read_file on
  wiki/traces, >=4 traces read before proposing), every read logged in the transaction
  journal. A study flag runs single-shot as a local ablation; the paper never ablated this,
  so effectiveness is unproven.
- Q5 (ledger lines 44-46, "Added requirements"): paper prompts (Appendix E.1-E.3) copied
  verbatim into references/paper-prompts/ with CC BY 4.0 attribution; local additions
  (attestation field, hash checks) live in a separate wrapper layer, never edited into the
  paper text.
- Closed model/serving facts (ledger lines 65-76) belong to PAR-06/PAR-07 requirement rows
  and the wiki draft, not to a sixth ADR — Q6 (first domain) and the Closed section are
  supporting facts, not new architectural decisions beyond Q1-Q5.
